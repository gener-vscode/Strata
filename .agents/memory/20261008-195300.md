## 2. Vision-token cost model (measured, do not re-derive)
- llama.cpp VisionEncoder formula: `tokens ≈ round(w/32) × round(h/32)`, cap `vision.max_tokens` (2048 server / 1024 per-turn in Gener).
- Predicted vs measured: 19×19 → 1 (1); 512×512 → 256 (observed 372 with prompt overhead); 1080p → 1008 (1096); 2560×1440 → 1980; 9855×790 → 1981 (2065).
- Encode wall-time is super-linear: 300 tok → 3.7 s; 720 tok → 21.7 s (8 thr) / 17.0 s (16 thr); 1024 tok → 31–41 s; 2048 tok → 151 s.
- `prompt_tokens` cannot be used to count base64 strings (base64 is not tokenized); only image-size deltas are informative. Transport (`data:` vs local absolute path) makes no difference: 483 prompt_tokens both ways.

## 4. Gener (VS Code extension) code findings — why images disappear
1. **Compact hard cut**: `src/core/task/utils/buildApiRequestContext.ts:327-364` → `findLastIndex(tool_use.name === 'compact')`, then `slice(lastCompactIdx + 1)`. Everything up to and including that pair (with its images) never enters the prompt. `getAllMessages()` is still complete (`src/core/task/fork.ts:141`, `context = [oldHistory, newHistory]`); trimming happens only at build time.
2. **Text-only filter**: `buildApiRequestContext.ts:66-105` `textifyContext()` ends with `content.filter(c => c.type === 'text')`; when a tool_use/tool_result pair fails to match ids (`:184-186`) all non-text blocks in that pair are dropped, even with `preserveBinary=true`.
3. **OpenAI transform keeps images**: `src/core/task/utils/openai-format.ts:109-182` replaces an image inside `tool_result` with the text "(see following user message for image)" and pushes an extra user message carrying `image_url: data:image/png;base64,…`. ⇒ the user's debugger observation ("all image blocks are present") is correct for turns after the compact boundary.
4. **Overflow path**: `buildApiRequestContext.ts:799-963` → `ContextTruncationError` → `buildContextTruncationResult`; if the profile advertises no image support the block is replaced by the text "_Gener reported you are text only model…_" and the file is written to temp. `fitContextWindow` (`src/utils/extractKeyContext.ts:52-149`, wasm `stripMessagesSync`) deletes from the middle (`mid = floor(len/2)`) and only retains COMPACT/WRITE_FILE/EDIT_FILE/ASK/PRESENT_PROPOSAL/ATTEMPT; truncated live pairs become the `[Context Window Safey Net]` truncated YAML seen at `api_conversation_history.json` idx 0.
5. **Defect found**: `src/shared/utils/token-counter.ts:261-305` `estimateTokens()` runs `stripBinaryContent()` first and returns `undefined` for `type==='image'` ⇒ Gener counts images as **0 tokens** while reality is ~256 (512²) to ~2000 (wide screenshots). This is the systematic under-count that explains "my estimate looks safe but the provider is already nearly full".
6. Other deletion paths: `trimOldHistory` (`MIN_KEEP_COUNT = 20`, only used by `clearTask()` / `Task.clearHistory()`), `stripEmptyMessages`, `stripUnresolvedContentBlocks`.
